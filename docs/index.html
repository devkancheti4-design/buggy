How it works

A real bug, a real repo, no hints.

Mealie is a 41,000-line FastAPI project with about 1,900 tests. One test went red and its traceback said only assert 200 == 423. This is what buggy did with it, replayed from the actual run. Nothing below is drawn that did not happen.

1
SUITE
One run of all 1,900 tests under per-test coverage. Which line did each test execute?
2
WHERE
Every line the failing test ran gets eight bits. The cause law ranks them. The bug crawls the executed lines and parks where the law ruled.
3
WHEN
Bisect in a throwaway worktree, the failing test carried into every revision.
4
WHY
The failing test traced against its nearest passing neighbour, to the first line where the paths part.
5
CHANGE
The mutation law: each suspect line altered one operator at a time in a copy of the project. Which edit turns the test green and breaks nothing?

What it reads

Evidence, measured. Never weighed.

Every source feeds a bit. No number in the body says how much a bit is worth: that is the law's job, and the law is a generated integer kernel you can read, run, and check exhaustively.

WHERE — the cause law

Which executed line is wrong

Per-test coverage, the commit bisect blamed, the first divergence from a passing run, the traceback's frames, the assertion's literals, recency.

EF_ALL every failing test ran it
EP_NONE no passing test did
IMPORT import-time only
BISECT the bad commit touched it
DIVERGE paths part here
FRAME a traceback frame
LITERAL the assertion's value
RECENT changed lately
MISSING — the omission law

Where code that does not exist belongs

A sixth of real fixes add a line the old code never ran. No executed line is wrong, so this law ranks where the path stopped looking.

ENDED the run's last line
NEXT the frontier stepped past
TARGET the assertion's function
HEAD a def or branch head
PASSONLY only passing tests reach
RAISED an exception, not an assert
DIVERGE paths part here
RECENT changed lately
CHANGE — the mutation law

Which line's content the outcome depends on

Coverage is testimony: the line was present. Mutation is an experiment: change it and see whether the failure survives. Where a single edit can flip the test, this finds the line in a 3,600-line file.

FLIP a mutant greens the test
ALL every failing test
CLEAN and no passing test breaks
EDIT an edit, not a deletion
MOVES the failure changes
UNIQUE the only line that flips
BREAKS every mutant breaks correct code
SILENT nothing changed

Where it does not help

  • Fixes that are many lines. No single-token mutant flips the test; the mutation law falls silent and the cause law's shortlist is what you get.
  • Omissions the failing test never runs. The omission law guesses where code belongs; on held-out real fixes it reaches the line in the top 5 twice of 35.
  • Suites that pin the wrong behaviour or constrain only a sum. The experiment is only as good as the tests; it says so instead of picking.
  • Old history. Bisect gives a bound, "at least as old as", capped by how far back the test can run, and far back "red" can mean the feature did not exist.
  • Speed. A fresh AI agent found the Mealie bug in 37 seconds. buggy took nine minutes, because it ran 1,900 tests. Its case is that it is free, deterministic, auditable, and does not get worse when the evidence is thin.

The hive, measured fairly

One queen, -j N worker buggys, each with its own copy of the project. The budget is counted when a line is assigned, so which lines get measured never depends on which worker was faster, and every worker measures with the same function the single lane uses. The harness runs each case both ways and diffs every bit and every rank.

Install

Two commands.

Your project needs pytest-cov in its own virtualenv; buggy finds a .venv beside the code by itself.

pip install buggy-cli
buggy doctor .        # can this install locate here?
buggy .               # the line, the commit, the repair — one run of the suite
buggy . -j 6 -v       # a hive of six worker buggys on the mutation lane, stages timestamped
buggy icon .          # the pixel bug: twitches while red, click it and it crawls to the line
buggy vscode-init .   # a task; results land in the Problems pane. Extension: vscode/buggy-0.1.0.vsix

The three laws are generated integer kernels with an independent oracle and a self-check each — src/buggy/laws/*.c — and the prompts that produced them are in the repo. AGPL-3.0.
